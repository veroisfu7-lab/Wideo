# ENGINE — как устроен шаблон Remotion + Three.js и как собрать новый ролик

Шаблон: `assets/template/`. Внутри два рабочих ролика-примера, проверенные ревьюером:
- `src/path/` — «Путь под ногами»: платформа-обрыв с зеркальным полом, ступени выезжают из темноты, фонарь с лучом, отъезд-раскрытие.
- `src/hourglass/` — «Песочные часы»: тела вращения (колбы, песок), тысячи частиц, разворот героя, прыжок, вис, подтягивание, ореол телефона, кривая камеры.
- `src/well/` — «Ведро и труба» (30 с, лучшая версия по оценке сэра): два героя с разным темпом, вода (струи, всплески, уровень в бочках), предметы в руках (ведро, лопата, секции трубы), смех с вылетающим «ХА», глянцевый пол с отражениями. Постановка — в `plan.ts` чистыми функциями, оттуда же события для звука.

Новый ролик собирается копированием ближайшего примера и заменой сцены.

## 1. Развернуть проект
```bash
cp -r "<skill>/assets/template" "<рабочая_папка>/<latin-name>"     # латиница без пробелов в имени папки проекта
cd "<рабочая_папка>/<latin-name>" && npm install                     # ~30 с; предупреждение про esbuild — безвредно
npx remotion still src/index.ts Path checks/test.png --frame=60 --scale=0.25   # проверка, что WebGL рендерит (angle)
```
Python-скрипты звука лежат в `tools/` (примеры), общие — в `<skill>/scripts/`.

## 3. Новый ролик — по шагам
0. `cp -r src/hourglass src/<имя>` (или `src/path`) — импорты `../anim`, `../Stickman`, `../Reel` при этом остаются верными; `cp tools/sfx_hg.py tools/sfx_<имя>.py`.
1. `src/<имя>/timeline.json` — задать `total` (330–490 кадров), `fadeStart = total−15`, `fadeLen 15`, текст (`line1`, `line2`, `line2Start` = кадр поворота + 1) и свои события.
2. `src/<имя>/Scene.tsx` — заменить декорации, позы и камеру. Персонажей рисовать только `Stickman`. Позы задавать функциями от кадра (детерминированно: Remotion рендерит кадры в любом порядке).
3. `src/<имя>/Main.tsx` — переименовать компонент; строка `<Composition id=... component=... durationInFrames={T.total} .../>` в `src/Root.tsx`.
4. `tools/sfx_<имя>.py` — путь к `src/<имя>/timeline.json`, имена выходных `public/sfx_<имя>.wav`, `checks/sfx_<имя>_events.csv`; события → звук на каждое движение.
5. Черновик: `npx remotion render src/index.ts <Id> out/draft.mp4 --scale=0.25`, затем `contact_sheet.py out/draft.mp4 checks/sheet.jpg`. Отладка «пустого кадра»: в примере path есть переключатели `--props='{"bloom":false}'` и `--props='{"hide":["beam"]}'` (`getInputProps`) — перенеси их в свою сцену при необходимости.
6. Звук: `python -I tools/sfx_<имя>.py` → `fetch_tiktok_sound.py` → `music_onsets.py <трек> <кадр поворота>` → `mix.sh` (с `DUR=total/30`) → `levels.py` (длительность последним аргументом).
7. Финал: `npx remotion render src/index.ts <Id> out/video_silent.mp4 --codec=h264 --crf=16`, потом
   `ffmpeg -i out/video_silent.mp4 -i out/audio.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest out/<имя>_vN.mp4`.

## 4. Числа сцены (проверены)
- **Камера:** `fov 28°` (длинный объектив, почти плоско), взгляд вниз 6–9°. Расстояние для нужного размера головы: `d = 0.30·1920 / (head_px · 2·tan14°)` ≈ `0.30·1920/(head_px·0.4986)`. Голова 76 px (7 %) → d ≈ 15.2; голова 106 px (9.8 %) → d ≈ 10.9. Видимая ширина = `2·d·tan14°·9/16`.
- **Медленный наезд** весь ролик ×1.04. **Отъезд-раскрытие** 50–75 кадров, `Easing.bezier(0.3,0,0.15,1)`. **Финальный наезд** на проигравшего ×1.08–1.10, inOut. Путь через 3 точки — одна квадратичная Безье с одним inOut (PITFALLS §4).
- **Bloom:** `luminanceThreshold 0.6, smoothing 0.3, intensity 0.13, mipmapBlur, radius 0.5` → класс A как в рефах. Класс B: HDR-цвет (×3–5) у эмиссивных или аддитивный ореол.
- **Цвета:** фон `#010002`; белый `#FDFDFD`, дальние конечности `#D7D4D8`; серый `#B2B0B4` / `#8F8D91`; декорации — шейдер граней (верх светлее, фасад с градиентом в чёрное), кромки `#5C595D`–`#C4C1C6`; акцент один (красный `#F62E2A`/`#EB1A2E`, тёплый свет `#FAE6AF`, экран `#CFE0FF`).
- **Зеркальный пол:** пример path, `Platform` (stencil write) + `<Stickman mirror>` + `EffectComposer stencilBuffer`. Сила 0.25, λ 0.36 м.
- **Шаги:** ступни по ключам/шагам → таз из ограничения длины ног (`pelvisFrom`) → сглаживание таза по 5–7 кадрам; руки маятником противоположно ногам; стопа на кадре касания (`0.35·inOut+0.65·t`).
- **Частицы:** `InstancedMesh`, позиция = функция кадра и хэша индекса; брызги со `floor` (оседают).
- **Тела вращения** (колбы, песок, воронки): `LatheGeometry` по профилю, пересчёт на каждом кадре. Объём впереди героя его закрывает (PITFALLS §3).

## 4a. Длинный ролик (25–30 с) и плавность — рецепт «Ведра и трубы»
- **Сначала раскадровка в «коротких» кадрах** (≈14 с, 420 кадров), потом растяжка. Растягивать равномерно нельзя: финал становится долгой статикой, удары и падения — слоумо.
- **Карта времени на каждого героя:** `Seg4 = [реал0, реал1, раскадр0, раскадр1]`, кусочно-линейно (`MAP_A`, `MAP_B` в plan.ts). Спокойные действия (шаги, копка, укладка) тянуть ×2–3, смех — ×6, а развороты, падение предмета и всё после поворота — почти ×1. Поворот ставить на ≈75 % длины (кадр 672 из 900), после него ≈7 с.
- **Всё, что считается «по накоплению»** (усталость, уровень воды, число рейсов), считать по реальному кадру, а не по раскадровке, иначе на стыках сегментов скачки. Повторяющиеся действия (смех, «ХА») — тоже по реальному времени, с постоянным периодом (каждые 7 кадров).
- **Физика (брызги, струи, всплески) — в реальных кадрах:** время старта события переводить через `realTimes()`, дальше `t = f − f0` без растяжки.
- **События для звука** пересчитывать в реальные кадры там же, в `events()`; звук читает уже готовые кадры.
- **Шаги в длинной версии:** ≈20 кадров на шаг (было 9–12), таз из длины ног, сглаживание по 5 кадрам.
- **Камера для двоих:** fov 28, взгляд сверху 15°, d 15.0→14.6 за ролик, финальный наезд до 12.8 на проигравшего. Герои на разной глубине (z −1.8 и +1.15), чтобы при проходах один был явно позади и выше.

## 4b. Глянцевый пол на всю сцену (не только платформа)
- Материал пола `#151216` пишет stencil=1, `renderOrder −2`; зеркальные `<Stickman mirror order={-1}>` (проп `order` есть в Stickman), `mirrorMat` аддитивный; `EffectComposer stencilBuffer`.
- Светящиеся предметы (бочка с водой) дают на полу отдельное аддитивное пятно цвета акцента (`floorGlowMat`) — это читается как отражение.
- Сэр отдельно напоминал про пол: в сценах с людьми на «улице» глянцевый пол ставить по умолчанию, матовый — только если так задумано сюжетом.
